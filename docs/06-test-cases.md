# 테스트 케이스

기능별 테스트 시나리오입니다.

## 1. 회원가입

### TC-1.1 정상 회원가입

| 항목 | 내용 |
|------|------|
| 전제조건 | 미가입 이메일 |
| 입력 | email: new@test.com, name: 테스트, password: 1234 |
| 예상결과 | 201 Created, member 객체 반환 |

### TC-1.2 중복 이메일 가입 시도

| 항목 | 내용 |
|------|------|
| 전제조건 | user1@example.com 이미 가입됨 |
| 입력 | email: user1@example.com, name: 중복, password: 1234 |
| 예상결과 | 409 Conflict |

### TC-1.3 필수값 누락

| 항목 | 내용 |
|------|------|
| 전제조건 | - |
| 입력 | email: test@test.com (name, password 누락) |
| 예상결과 | 400 Bad Request |

## 2. 로그인

### TC-2.1 정상 로그인

| 항목 | 내용 |

### TC-2.3 미가입 이메일

| 항목 | 내용 |
|------|------|
| 전제조건 | - |
| 입력 | email: notexist@test.com, password: 1234 |
| 예상결과 | 404 Not Found |

## 3. 상품 등록

### TC-3.1 정상 등록

| 항목 | 내용 |
|------|------|
| 전제조건 | 로그인 상태 (토큰 보유) |
| 입력 | productName: 테스트상품, description: 설명, price: 10000, photo: image.jpg |
| 예상결과 | 201 Created, 상품 정보 반환 |

### TC-3.2 이미지 누락

| 항목 | 내용 |
|------|------|
| 전제조건 | 로그인 상태 |
| 입력 | productName, description, price만 (photo 없음) |
| 예상결과 | 400 Bad Request |

### TC-3.3 미인증 상태

| 항목 | 내용 |
|------|------|
| 전제조건 | 토큰 없음 |
| 입력 | 정상 데이터 |
| 예상결과 | 401 Unauthorized |

### TC-3.4 만료된 토큰

| 항목 | 내용 |
|------|------|
| 전제조건 | 만료된 토큰 사용 |
| 입력 | 정상 데이터 |
| 예상결과 | 403 Forbidden |

## 4. 상품 목록 조회

### TC-4.1 기본 조회

| 항목 | 내용 |
|------|------|
| 전제조건 | 로그인 상태, 상품 15개 존재 |
| 입력 | GET /sales |
| 예상결과 | 200 OK, 10개 반환, count: 15, hasNext: true |

### TC-4.2 페이지네이션

| 항목 | 내용 |
|------|------|
| 전제조건 | 상품 15개 존재 |
| 입력 | GET /sales?page=2&size=10 |
| 예상결과 | 5개 반환, hasNext: false |

### TC-4.3 검색

| 항목 | 내용 |
|------|------|
| 전제조건 | "양파" 포함 상품 3개 존재 |
| 입력 | GET /sales?q=양파 |
| 예상결과 | 3개 반환, count: 3 |

### TC-4.4 내 상품만 조회

| 항목 | 내용 |
|------|------|
| 전제조건 | user1이 5개 상품 등록 |
| 입력 | GET /sales?email=user1@example.com |
| 예상결과 | user1의 상품 5개만 반환 |

---

## 5. 상품 상세 조회

### TC-5.1 정상 조회

| 항목 | 내용 |

## 6. 상품 삭제

### TC-6.1 본인 상품 삭제

| 항목 | 내용 |
|------|------|
| 전제조건 | user1 로그인, user1의 상품 ID 1 |
| 입력 | DELETE /sales/1 |
| 예상결과 | 200 OK, 상품 조회 시 안 보임 |

### TC-6.2 타인 상품 삭제 시도

| 항목 | 내용 |
|------|------|
| 전제조건 | user1 로그인, user2의 상품 ID 5 |
| 입력 | DELETE /sales/5 |
| 예상결과 | 403 Forbidden |

### TC-6.3 삭제 시 찜 데이터 정리

| 항목 | 내용 |
|------|------|
| 전제조건 | 상품 1에 찜 3개 존재 |
| 입력 | DELETE /sales/1 |
| 예상결과 | 상품 삭제됨, 해당 찜 데이터도 삭제됨 |

## 7. 찜하기

### TC-7.1 찜 추가

| 항목 | 내용 |
|------|------|
| 전제조건 | user1 로그인, 상품 1 찜 안 함 |
| 입력 | POST /sales/1/favorite |
| 예상결과 | 200 OK, isFavorite: true, favoriteCount 증가 |

### TC-7.2 찜 해제

| 항목 | 내용 |
|------|------|
| 전제조건 | user1 로그인, 상품 1 찜함 |
| 입력 | DELETE /sales/1/favorite |
| 예상결과 | 200 OK, isFavorite: false, favoriteCount 감소 |

### TC-7.3 중복 찜 (멱등성)

| 항목 | 내용 |
|------|------|
| 전제조건 | user1 로그인, 상품 1 이미 찜함 |
| 입력 | POST /sales/1/favorite |
| 예상결과 | 200 OK, isFavorite: true (에러 아님) |

### TC-7.4 존재하지 않는 상품 찜

| 항목 | 내용 |
|------|------|
| 전제조건 | - |
| 입력 | POST /sales/99999/favorite |
| 예상결과 | 404 Not Found |

## UI 테스트

### TC-UI-1 검색 디바운스

| 항목 | 내용 |
|------|------|
| 동작 | 검색창에 빠르게 "양파마켓" 입력 |
| 예상결과 | 입력 완료 후 300ms 뒤에 1번만 API 호출 |

### TC-UI-2 찜 Optimistic Update

| 항목 | 내용 |
|------|------|
| 동작 | 하트 버튼 클릭 |
| 예상결과 | 즉시 UI 변경, 실패 시 롤백 |

### TC-UI-3 보기 방식 유지

| 항목 | 내용 |
|------|------|
| 동작 | 리스트 보기로 변경 후 페이지 새로고침 |
| 예상결과 | 리스트 보기 유지 (localStorage) |

### TC-UI-4 검색어 URL 유지

| 항목 | 내용 |
|------|------|
| 동작 | "양파" 검색 후 URL 복사, 새 탭에서 열기 |
| 예상결과 | 검색어 유지, 검색 결과 표시 |

### TC-UI-5 로그아웃

| 항목 | 내용 |
|------|------|
| 동작 | 마이페이지에서 로그아웃 클릭 |
| 예상결과 | 확인 다이얼로그, 로그인 화면 이동, 토큰 삭제 |
